# 叙事：怎么把一个原理讲成 3–5 分钟的片子

## 结构模板（Token 范例对照）

| 段落 | 作用 | Token 范例 | 占比 |
|---|---|---|---|
| 0 钩子 | 抛出一个反直觉的现象，或者一个日常问题 | “今天天气怎么样？”——“今天”被拆开了，“天天”反而粘在一起 | 10–15% |
| 1–N 机制 | 由外往里剥，每章只讲一步，按数据流动的顺序 | 切积木 → 编号 → 意思空间 → 注意力 → 猜下一块 | 60–70% |
| 回收 | 用刚讲的机制，解释开头的现象，以及两三个相关的怪现象 | 忘事（上下文窗口）、胡说（像≠对）、按 Token 收费 | 15–20% |
| 收尾 | 拉远镜头看全局，给一个大数字，或者抛一个开放问题 | “二十万块积木里一块一块地接龙……这算不算思考？评论区聊聊” | 5–10% |

## 写脚本的原则

1. **一个例子贯穿全片。** 选一个观众天天碰到的东西（一句提问、一次转账），后面每一章都继续用它，不要每章换一个新例子。
2. **钩子要具体到能截图。** “AI 为什么数不清 strawberry 里有几个 r”比“AI 是怎么工作的”强得多。同题材里播放量最高的那些片子，赢在钩子，不在画面。
3. **事实要实测。** 能跑代码验证的就跑，比如分词器、哈希值、真实的编号；不能实测的，在画面上标“示意”。
4. **每句话对应一个画面动作。** 写完逐句问自己：这句话说的时候，画面上发生了什么？答不上来，就删掉这句，或者合并到别的句子里。
5. **口语，短句。** 一句不超过 25 字，多用逗号断开（配音的停顿和字幕的切分都依赖标点）。少用术语，非用不可的，先比喻再给名字：“这些积木，就叫 Token，中文叫‘词元’。”
6. **比喻只用一个，并且一直用下去。** 积木就是积木，中途不要再引入“乐高”“拼图”“火车车厢”这些别的比喻。
7. **结尾抛一个开放问题**，引导观众到评论区讨论。

## script.txt 格式

```
# 注释行
[c0 开场]
rag_a01|N|neutral|你问AI公司的报销流程，它答得头头是道。
rag_a02|N|neutral|可它从没见过你们公司的文件——它是怎么知道的？
[c1 找资料]
rag_b01|N|neutral|……
```

- `[c1 找资料]`：章节号加章节名，章节名会显示在左下角的章节牌上；`c0` 是开场，不显示章节牌。
- 每句的格式是 `id|说话人|情绪|文本`。id 建议用“片名缩写_章节字母序号”，比如 `rag_b03`，避免不同片子的配音文件撞名。
- 说话人字母在 `voices.json`（MiniMax）或 `voices_edge.json`（Edge）里映射到具体音色；情绪一般用 `neutral`。

## 时长估算

中文旁白大约每秒 4.5–5 个字（语速 1.06 时）。3 分半的片子，旁白大约 170 秒，即 750–850 字，分 50 句左右；剩下的时间是章节间隔和关键画面后的留白。
